# Плівкова камера

Статичний веб-застосунок на чистому HTML, CSS і vanilla JS (ES modules, без фреймворків і збірки). Відкриваєте сторінку на телефоні, бачите старий плівковий фотоапарат у стилі скевоморфізму перших iOS: шкіряний корпус зі строчкою, алюмінієва панель, хромований видошукач, механічний лічильник кадрів, вибір камери (лінзи), плівки й спалаху. Спуск обробляє готовий кадр з камери власним WebGL-пайплайном, який імітує плівку. Вбудована обробка iPhone (Smart HDR, Deep Fusion тощо) не змінюється: ми працюємо з уже готовим кадром.

## Файли

| Файл | Призначення |
| --- | --- |
| `index.html`, `styles.css` | розмітка й оформлення корпусу |
| `app.js` | камера, UI, цикл спуску, лічильник, збереження, перемикання режимів |
| `darkroom.js`, `shake.js`, `negative.js` | режим «Темна кімната»: проявка трусінням, негативи, позитиви, перегляд |
| `pipeline.js` | криві, `.cube`, параметри кадру, WebGL-шейдери |
| `lenses.js`, `zoom.js` | розпізнавання модулів камери телефона й вимірювання збільшення телеоб'єктива |
| `cameras.js` | профілі камер (оптика) |
| `films.js` | профілі плівок (колір) |
| `random.js` | seeded-генератор і випадкові значення кадру |
| `tests/` | unit-тести без залежностей |

## Запуск локально

```bash
python3 -m http.server 8000
# або
npx serve
```

Відкрийте `http://localhost:8000`. `getUserMedia` працює на `localhost` і на HTTPS, на звичайному HTTP у мережі камера не запуститься. Щоб перевірити пайплайн без камери, додайте `?demo=1`: замість камери піде тестова картинка.

## Тести

```bash
node --test
```

Потрібен Node 18+. Тести покривають `random.js` (межі всіх значень на тисячах seed, відтворюваність, частоти подій) і чисту частину `pipeline.js` (криві, `.cube`, параметри, CPU-еталон кольору: з вимкненими ефектами кадр збігається з входом).

### Перевірка шейдерів

GLSL у node не запускається, тому тести перевіряють чисту логіку. Шейдери перевіряються в браузері: відкрийте `?demo=1`, зніміть кадр і в консолі порівняйте `filmDebug.pipeline.readPixels()` з вхідним зображенням при нейтральних профілях (`NEUTRAL_CAMERA`, `NEUTRAL_FILM`, `NEUTRAL_FRAME`). Для відлагодження останній кадр доступний як `filmDebug.last`.

## Як це працює

1. `getUserMedia` (задня камера, ідеально 1920×1080), відео виводиться в `<video playsinline muted>`.
2. На спуску кадр центрально обрізається під формат (3:2 за замовчуванням або 1:1; на портретному екрані 3:2 стає 2:3), малюється в offscreen `canvas` і передається в WebGL як текстура.
3. `rollFrame(seed)` кидає випадкові значення кадру, `developFilm(плівка, seed)` складає профіль для «Просрочки» й «Намотки», `computeParams(камера, плівка, кадр)` зводить усе в параметри шейдерів.
4. Проходи: лінза (бочка/подушка, хроматична аберація, розмиття країв) → halation → фінал (різкість, експозиція, баланс білого, мікс каналів, віньєтка, спалах, крива плівки, 3D LUT, насиченість, тонування, вуаль, зерно, світлова протічка, пил, ремджет і перфорація).
5. `canvas.toBlob("image/jpeg", 0.92)`, далі `navigator.share({ files })` або `a[download]`. Ім'я файлу: `film-YYYYMMDD-HHMMSS-NN.jpg`.

Максимальний розмір виводу 2048 px по довшій стороні. Готовий кадр показується без рамок.

### Камери

Десять профілів (`cameras.js`): «iPhone» (без ефектів, чистий режим), Leica M6, Contax T2, Canon AE-1, Olympus mju-II, Yashica T4, Зеніт-Е, Lomo LC-A, Holga 120N, Diana F+. Поля: `vignetteStrength`, `vignetteRadius`, `edgeSoftness`, `chromaticAberration`, `barrelDistortion`, `glowAmount`, `glowThreshold`, `sharpness` (від'ємне значення дає м'якість); межі в `CAMERA_LIMITS`. Необов'язкове `leakMul` збільшує шанс світлової протічки (Holga ×2.5, Diana ×2).

### Плівки

Профілі в `films.js` наближають вигляд реальних емульсій, а не вимірюють їх. Групи в списку:

| Бренд | Плівки |
| --- | --- |
| Kodak | Gold 200, Ultramax 400, Portra 400, Ektar 100, Ektachrome E100 (слайд), Tri-X 400 (ч/б) |
| Fujifilm | Fujicolor C200, Superia X-TRA 400, Pro 400H, Velvia 50 (слайд) |
| Ilford | HP5 Plus 400 (ч/б) |
| CineStill | 800T: вольфрамовий баланс і сильне червоне гало |
| Lomography | LomoChrome Purple, Redscale XR |
| Agfa | Vista 200 |
| Особливі | Просрочка, Намотка |

**Експозиція й чорне.** Усі реальні плівки знімаються трохи темніше за нейтральну експозицію (`EXPOSURE_BIAS_EV = -0.45` EV, поле `exposureBias`), а в тональних кривих піднятий чорний зменшено до 30 % (`BLACK_LIFT_SCALE`) і тіні трохи поглиблені (`TOE_DEPTH`), тож чорні глибші, а півтони й світла майже на місці. Для Kodak Gold 200 чорне стало 3 замість 10 з 255, середній сірий 115 замість 130, світла 234 замість 241. Плівка «Null» і чистий режим не змінюються.

Поля плівки: `tonecurve`, `channelCurves`, `mix` (3×3 мікс каналів: ч/б і «хімічні» плівки), `saturation`, `greenCyanBoost`, `shadowTint`/`highlightTint` (обмежено `TINT_LIMIT`), `grainAmount`, `grainSize`, `halation` (червоне світіння плівки без remjet-шару), `fog` (вуаль), `lut`. Для `lut` вкажіть URL файлу `.cube` (`LUT_3D_SIZE`, домен 0–1). Якщо файлу немає чи він зіпсований, працюють самі криві.

**Просрочка.** Для кожного кадру береться випадкова плівка зі списку й «старіє» на 4–28 років: піднятий чорний і приглушений білий, менший контраст і насиченість, зсув кольору (пурпурний, зелений, жовтий або блакитний), сильніше зерно, молочна плямиста вуаль. У підписі кадру видно, що саме випало.

**Намотка.** Кіноплівка Vision3 (500T, 250D або 200T, випадково на кадр), «засунута» у фотоапарат: кінематографічний колір (500T синіє при денному світлі), сильне червоне гало, зерно, чорні цятки ремджету (близько 60 % кадрів) і смуги з перфорацією та крайовим написом зверху й знизу.

### Спалах

Кнопка з блискавкою в верхній панелі, поруч із кнопкою дати (обидві згруповані зліва від лічильника). Якщо браузер дозволяє керувати ліхтариком (Android Chrome), на спуску він справді вмикається на мить. iOS Safari цього не дає, тож скрізь додається і імітація прямого світла: гарячий центр, темніші краї, сила 0.8–1.2 на кадр (з ліхтариком половина). При першому ввімкненні застосунок показує, який режим діє.

### Модель зерна

Зерно описане в `grain.js` і залежить від таких речей:

| Що | Як воно впливає | Як це зроблено |
| --- | --- | --- |
| Структура | Це не білий шум, а грудочки: у спектрі немає найвищих частот (грудочки мають розмір) і немає найнижчих (великих плям). | Текстура 256×256 із гаусового шуму: згладжування мінус сильніше розмиття (band-pass), без швів. Сусідні пікселі лише трохи корелюють (~0.3), далі кореляції немає: дрібні м'які зернини без «черв'ячків». |
| Колір | Три шари барвників зернять незалежно, у ч/б одне срібло. | Чотири незалежні поля (R, G, B, спільне). Колірна частка `grainChroma`: 0.3 для кольорових, 0 для ч/б. |
| Чутливість | Більше ISO, крупніше зерно. | `grainAmount` і `grainSize` плівок ростуть з ISO (Ektar 100 тонке, Tri-X 400 крупне). |
| Розмір відносно кадру | На великому негативі те саме зерно займає меншу частку кадру. | Зернина на готовому кадрі близько 1–1.5 пікселя (не менше `GRAIN_MIN_PX`) і рахується від ширини кадру (`GRAIN_REF_WIDTH`); камери на плівці 120 (Holga, Diana) мають зерно ×0.6 за розміром і ×0.85 за силою. |
| Тони | Найпомітніше в тінях і півтонах, у світлах і глибокому чорному слабше. | Зерно додається до сигналу до характеристичної кривої плівки, тож її пологі ділянки (ніжка й плече) стискають його; у тінях ще підсилене. |
| Експозиція | Недоекспонована плівка зернить сильніше, переекспонована дрібніше. | Множник 2^(−0.25·EV), тобто ≈ ×1.19 на стоп недоекспозиції. Діє і на випадковий зсув експозиції кадру, і на засвіт. |
| Стан плівки | Просрочка й дешеві кіноплівки зернять більше. | Закладено в профілях «Просрочки» й «Намотки». |
| Сила | У півтонах лише кілька рівнів з 255: помітне в гладких ділянках (небо, шкіра), не «пісок». | `GRAIN_STRENGTH` × `grainAmount` плівки: Gold 200 ≈ 5 рівнів, Tri-X 400 ≈ 8. |

### Інтерфейс

Весь інтерфейс набрано моноширинним технічним шрифтом (SF Mono на iOS, Menlo, Consolas). Вибір камери й плівки показується на табло в стилі рідкокристалічного індикатора. Назви брендів прибрано: камери й плівки названо за характером (наприклад «Дальномір», «C200 · Тепла»; літера C колір, S слайд, BW чорно-біла, T вольфрам, X експериментальна). Спуск — точений метал із кільцевими канавками, залитими червоною фарбою.

### Режим «Темна кімната»

Кнопка «Кімната» у верхній панелі перемикає режим. У звичайному режимі кадр відкривається одразу, а стрічка й важіль «перемотати» працюють як раніше. У режимі темної кімнати плівка окрема (свій лічильник і своє сховище в IndexedDB, звичайна плівка не чіпається):

1. **Зйомка.** Спуск знімає кадр, але нічого не показує: лише клац, спалах і лічильник. Мініатюра біля спуску відкриває список кадрів, які ще не видно (тільки номери).
2. **Плівка кінчається** на 36-му кадрі або коли ви **відрізаєте** її важелем (протягніть ручку зліва направо, хоча б один кадр уже має бути знятий).
3. **Проявка.** Натисніть «Почати проявку» й потрусіть телефон: акселерометр (`devicemotion`) рахує різкі рухи, шкала проходить «Проявник, Зупинка, Фіксаж, Промивка» (10–15 секунд енергійного трусіння). iOS питає дозвіл на рух; без датчика працює резервний режим: водіть пальцем по баночці.
4. **Негативи.** Смужки з перфорацією, помаранчева основа, інвертовані кольори (негатив рахується з кадру формулою з `negative.js`). Тап по кадру відкриває його, далі гортайте свайпом.
5. **Позитив.** «Перевести в позитив» інвертує кадри по черзі й відкриває звичайну галерею зі збереженням («Зберегти все»).
6. **Нова плівка** видаляє кадри (після підтвердження) і повертає камеру. Поки йде проявка, потік камери вимкнено, а при поверненні в камеру відновлюється без нового запиту дозволу.

Етап і кадри зберігаються: після перезавантаження ви повертаєтесь туди, де зупинились. Перемкнувшись у звичайний режим під час проявки, ви повертаєтесь до камери; кімната чекає, поки ви знову ввімкнете її режим.

### Розкладка під iPhone

Видошукач займає весь вільний простір між верхньою панеллю й органами керування (`container-type: size`, розмір береться в `cqw`/`cqh`), тому нічого не вилазить ні в Safari (де видима висота близько 650 pt, з панеллю браузера), ні в додатку з головного екрана (852 pt на iPhone 15 Pro). На невисокому екрані стискаються панелі, а табло ховається. Під рядком стану в додатку є чорна смуга за `env(safe-area-inset-top)`, щоб білий час не зливався з металом.

Збільшення телеоб'єктива на iPhone визначається за розміром екрана (`teleStrategy` у `zoom.js`): 393×852 це 3×, 402×874 і 440×956 це 5×. Вимірювання по кадрах лишилось лише для неоднозначного 430×932 (14 Pro Max проти 15 Pro Max) і для Android, бо на близьких предметах воно помилялось.

### Експозиція

Малий барабан «Експоз.» біля вибору камери додає поправку від −1 до +1 EV кроками по ⅓, як на справжній камері. Вона додається до зсуву плівки й випадкової експозиції кадру та діє у всіх режимах, у тому числі в чистому (там це свідомий вибір користувача, за замовчуванням 0). Вибір зберігається.

### Модулі камери

Під видошукачем з'являються кнопки **0.5× · 1× · 3×** (або **5×**), якщо в телефона є окремі об'єктиви. Кнопка справді перемикає потік: застосунок просить у браузера `deviceId` потрібного об'єктива (`getUserMedia` з `deviceId: {exact}`), а список бере з `enumerateDevices()` і впізнає за підписами («Back Ultra Wide Camera», «Back Camera», «Back Telephoto Camera»; підписи браузер показує лише після дозволу на камеру, тож список з'являється одразу після першого старту). Віртуальні «Dual/Triple» ховаються, якщо є окремі об'єктиви. Видошукач при цьому нічого не показує, потік просто змінюється.

Скільки разів телеоб'єктив збільшує (3× чи 5× залежить від моделі), браузер не каже. Тому спершу показується припущення за екраном (402×874 і 440×956: 5×, решта 3×), а при першому перемиканні на телеоб'єктив застосунок порівнює кадр основної камери з кадром телеоб'єктива (`zoom.js`: нормована взаємна кореляція центрального кропу, кандидати 2, 2.5, 3, 4, 5, 8) і запам'ятовує виміряне значення для цього пристрою; якщо кадри не збіглися (темно, рівна стіна), лишається припущення. Вибраний об'єктив зберігається; якщо він зник, відкривається основна камера. Перевірено в демо-режимі (`?demo=1&tele=5`); на справжньому iPhone не тестувалось.

### Чистий режим

Перший пункт барабана камер це «iPhone» (без жодних оптичних ефектів), а плівок «Null» (без плівки: колір і зерно не змінюються). Разом вони дають чистий кадр, такий, як його віддав телефон: без віньєтки, аберацій, зерна, зсуву кольору й випадкових подій (протічок, пилу, засвіту, зсуву експозиції). Можна змішувати: «iPhone» з реальною плівкою дає лише колір і зерно, реальна камера з «Null» лише оптику. Без плівки випадкових подій нема.

### Барабани вибору

Камера й плівка вибираються барабанами: потягніть вертикально (або колесом миші, клавішами ↑/↓), пункт «магнітно» стає в центральну смугу, при кожному пункті є клацання й вібро. Барабан «загинається» за циліндр: далекі пункти нахилені й блідіші.

### Віброзвук

`haptics.js`: на Android (Chrome) використовується `navigator.vibrate`. iOS Safari цього API не має, тому для нього є неофіційний обхід через `<input type="checkbox" switch>` (працює від iOS 17.4 і лише всередині жесту), тож на iPhone вібро не гарантоване. Клацання звучать скрізь.

### Стійкість камери

Систему може зупинити відео (діалог, перемикання застосунків, перерваний потік): тоді знімок виходить із застиглим кадром. Перед кожним знімком і після перемотки застосунок перевіряє, що потік живий і кадри надходять (`requestVideoFrameCallback`), будить відео, а якщо потік помер, відкриває камеру заново.

### Дата на кадрі

Кнопка з календарем у верхній панелі (світиться, коли дата ввімкнена; за замовчуванням ввімкнена). На кадр внизу праворуч додається помаранчевий семисегментний штамп у форматі `'РР ММ ДД` із сяйвом, як у плівкових мильниць. На «Намотці» він стоїть над смугою перфорації. Вибір зберігається.

### Випадковість на кадр

| Подія | Ймовірність / межі |
| --- | --- |
| експозиція | ±0.3 EV, рівномірно |
| баланс білого | температура ±300 K, відтінок ±5 |
| зерно | множник 0.8–1.3 |
| світлова протічка | 8–12 % (× `leakMul` камери) |
| пил (1–5 плям, 0–2 подряпини) | 15 % |
| засвіт | 5 %, +0.5…1 EV |
| м'який фокус (весь кадр або краї) | 10 % |
| спалах (якщо ввімкнений) | сила 0.8–1.2 |

Усі значення зберігаються в метаданих кадру й виводяться в консоль (`[кадр N] камера + плівка`), останній кадр також доступний як `filmDebug.last`.

## Деплой на GitHub Pages

Workflow `.github/workflows/pages.yml` проганяє тести й публікує вміст репозиторію після пушу в `main`. У налаштуваннях репозиторію: Settings → Pages → Source: GitHub Actions.

## Як відкрити на телефоні й додати на головний екран

1. Відкрийте `https://<user>.github.io/<repo>/` у Safari (iPhone) або Chrome (Android).
2. Дозвольте доступ до камери.
3. iPhone: кнопка «Поділитися» → «На екран “Додому”». Android: меню ⋮ → «Установити застосунок» / «Додати на головний екран».

Лічильник кадрів, обрані камера, плівка й формат зберігаються в `localStorage`.

### Запит доступу до камери

Застосунок викликає `getUserMedia` один раз і не вимикає потік, коли сторінка ховається, тож листок «Поділитися» чи перемикання застосунків нового запиту не викликають. Але iOS Safari питає знову при кожному відкритті сторінки, поки дозвіл не збережений: у Safari торкніться `aA` в адресному рядку → «Налаштування вебсайту» → «Камера» → «Дозволити» (або Налаштування → Safari → Камера). Застосунок, доданий на головний екран, iOS питає при кожному запуску незалежно від цього: це обмеження WebKit, яке сторінка обійти не може.
