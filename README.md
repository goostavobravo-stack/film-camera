# Плівкова камера

Статичний веб-застосунок на чистому HTML, CSS і vanilla JS (ES modules, без фреймворків і збірки). Відкриваєте сторінку на телефоні, бачите старий плівковий фотоапарат у стилі скевоморфізму перших iOS: шкіряний корпус зі строчкою, алюмінієва панель, хромований видошукач, механічний лічильник кадрів, вибір камери (лінзи), плівки й спалаху. Спуск обробляє готовий кадр з камери власним WebGL-пайплайном, який імітує плівку. Вбудована обробка iPhone (Smart HDR, Deep Fusion тощо) не змінюється: ми працюємо з уже готовим кадром.

## Файли

| Файл | Призначення |
| --- | --- |
| `index.html`, `styles.css` | розмітка й оформлення корпусу |
| `app.js` | камера, UI, цикл спуску, лічильник, збереження |
| `pipeline.js` | криві, `.cube`, параметри кадру, WebGL-шейдери |
| `cameras.js` | профілі камер (оптика) |
| `films.js` | профілі плівок (колір) |
| `random.js` | seeded-генератор і випадкові значення кадру |
| `tests/` | unit-тести без залежностей |

## Запуск локально

```bash
python3 -m http.server 8000
# або
npx serve
```

Відкрийте `http://localhost:8000`. `getUserMedia` працює на `localhost` і на HTTPS, на звичайному HTTP у мережі камера не запуститься. Щоб перевірити пайплайн без камери, додайте `?demo=1`: замість камери піде тестова картинка.

## Тести

```bash
node --test
```

Потрібен Node 18+. Тести покривають `random.js` (межі всіх значень на тисячах seed, відтворюваність, частоти подій) і чисту частину `pipeline.js` (криві, `.cube`, параметри, CPU-еталон кольору: з вимкненими ефектами кадр збігається з входом).

### Перевірка шейдерів

GLSL у node не запускається, тому тести перевіряють чисту логіку. Шейдери перевіряються в браузері: відкрийте `?demo=1`, зніміть кадр і в консолі порівняйте `filmDebug.pipeline.readPixels()` з вхідним зображенням при нейтральних профілях (`NEUTRAL_CAMERA`, `NEUTRAL_FILM`, `NEUTRAL_FRAME`). Для відлагодження останній кадр доступний як `filmDebug.last`.

## Як це працює

1. `getUserMedia` (задня камера, ідеально 1920×1080), відео виводиться в `<video playsinline muted>`.
2. На спуску кадр центрально обрізається під формат (3:2 за замовчуванням або 1:1; на портретному екрані 3:2 стає 2:3), малюється в offscreen `canvas` і передається в WebGL як текстура.
3. `rollFrame(seed)` кидає випадкові значення кадру, `developFilm(плівка, seed)` складає профіль для «Просрочки» й «Намотки», `computeParams(камера, плівка, кадр)` зводить усе в параметри шейдерів.
4. Проходи: лінза (бочка/подушка, хроматична аберація, розмиття країв) → halation → фінал (різкість, експозиція, баланс білого, мікс каналів, віньєтка, спалах, крива плівки, 3D LUT, насиченість, тонування, вуаль, зерно, світлова протічка, пил, ремджет і перфорація).
5. `canvas.toBlob("image/jpeg", 0.92)`, далі `navigator.share({ files })` або `a[download]`. Ім'я файлу: `film-YYYYMMDD-HHMMSS-NN.jpg`.

Максимальний розмір виводу 2048 px по довшій стороні. Готовий кадр показується без рамок.

### Камери

Дев'ять профілів лінз (`cameras.js`): Leica M6, Contax T2, Canon AE-1, Olympus mju-II, Yashica T4, Зеніт-Е, Lomo LC-A, Holga 120N, Diana F+. Поля: `vignetteStrength`, `vignetteRadius`, `edgeSoftness`, `chromaticAberration`, `barrelDistortion`, `glowAmount`, `glowThreshold`, `sharpness` (від'ємне значення дає м'якість); межі в `CAMERA_LIMITS`. Необов'язкове `leakMul` збільшує шанс світлової протічки (Holga ×2.5, Diana ×2).

### Плівки

Профілі в `films.js` наближають вигляд реальних емульсій, а не вимірюють їх. Групи в списку:

| Бренд | Плівки |
| --- | --- |
| Kodak | Gold 200, Ultramax 400, Portra 400, Ektar 100, Ektachrome E100 (слайд), Tri-X 400 (ч/б) |
| Fujifilm | Fujicolor C200, Superia X-TRA 400, Pro 400H, Velvia 50 (слайд) |
| Ilford | HP5 Plus 400 (ч/б) |
| CineStill | 800T: вольфрамовий баланс і сильне червоне гало |
| Lomography | LomoChrome Purple, Redscale XR |
| Agfa | Vista 200 |
| Особливі | Просрочка, Намотка |

Поля плівки: `tonecurve`, `channelCurves`, `mix` (3×3 мікс каналів: ч/б і «хімічні» плівки), `saturation`, `greenCyanBoost`, `shadowTint`/`highlightTint` (обмежено `TINT_LIMIT`), `grainAmount`, `grainSize`, `halation` (червоне світіння плівки без remjet-шару), `fog` (вуаль), `lut`. Для `lut` вкажіть URL файлу `.cube` (`LUT_3D_SIZE`, домен 0–1). Якщо файлу немає чи він зіпсований, працюють самі криві.

**Просрочка.** Для кожного кадру береться випадкова плівка зі списку й «старіє» на 4–28 років: піднятий чорний і приглушений білий, менший контраст і насиченість, зсув кольору (пурпурний, зелений, жовтий або блакитний), сильніше зерно, молочна плямиста вуаль. У підписі кадру видно, що саме випало.

**Намотка.** Кіноплівка Vision3 (500T, 250D або 200T, випадково на кадр), «засунута» у фотоапарат: кінематографічний колір (500T синіє при денному світлі), сильне червоне гало, зерно, чорні цятки ремджету (близько 60 % кадрів) і смуги з перфорацією та крайовим написом зверху й знизу.

### Спалах

Кнопка з блискавкою зліва від спуску. Якщо браузер дозволяє керувати ліхтариком (Android Chrome), на спуску він справді вмикається на мить. iOS Safari цього не дає, тож скрізь додається і імітація прямого світла: гарячий центр, темніші краї, сила 0.8–1.2 на кадр (з ліхтариком половина). При першому ввімкненні застосунок показує, який режим діє.

### Випадковість на кадр

| Подія | Ймовірність / межі |
| --- | --- |
| експозиція | ±0.3 EV, рівномірно |
| баланс білого | температура ±300 K, відтінок ±5 |
| зерно | множник 0.8–1.3 |
| світлова протічка | 8–12 % (× `leakMul` камери) |
| пил (1–5 плям, 0–2 подряпини) | 15 % |
| засвіт | 5 %, +0.5…1 EV |
| м'який фокус (весь кадр або краї) | 10 % |
| спалах (якщо ввімкнений) | сила 0.8–1.2 |

Усі значення зберігаються в метаданих кадру й виводяться в консоль (`[кадр N] камера + плівка`), останній кадр також доступний як `filmDebug.last`.

## Деплой на GitHub Pages

Workflow `.github/workflows/pages.yml` проганяє тести й публікує вміст репозиторію після пушу в `main`. У налаштуваннях репозиторію: Settings → Pages → Source: GitHub Actions.

## Як відкрити на телефоні й додати на головний екран

1. Відкрийте `https://<user>.github.io/<repo>/` у Safari (iPhone) або Chrome (Android).
2. Дозвольте доступ до камери.
3. iPhone: кнопка «Поділитися» → «На екран “Додому”». Android: меню ⋮ → «Установити застосунок» / «Додати на головний екран».

Лічильник кадрів, обрані камера, плівка й формат зберігаються в `localStorage`.

### Запит доступу до камери

Застосунок викликає `getUserMedia` один раз і не вимикає потік, коли сторінка ховається, тож листок «Поділитися» чи перемикання застосунків нового запиту не викликають. Але iOS Safari питає знову при кожному відкритті сторінки, поки дозвіл не збережений: у Safari торкніться `aA` в адресному рядку → «Налаштування вебсайту» → «Камера» → «Дозволити» (або Налаштування → Safari → Камера). Застосунок, доданий на головний екран, iOS питає при кожному запуску незалежно від цього: це обмеження WebKit, яке сторінка обійти не може.
